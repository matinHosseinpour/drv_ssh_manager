# اتصال مدار به GPT با یک URL

نشانی نهایی این نصب:

```text
https://server.darvishipioneers.com/mcp
```

این نشانی **بعد از اجرای موفق `sudo bash script.sh` روی سرور و آماده‌شدن DNS و HTTPS** قابل استفاده است. تغییر فایل‌های سورس به معنی استقرار یا نصب پلاگین در حساب GPT نیست.

## مسیر کاربر

1. در [ChatGPT Plugins](https://chatgpt.com/plugins)، گزینهٔ `+` و سپس `Add custom MCP server` را باز کنید.
2. URL بالا را وارد کنید. در سطحی که انتخاب نوع احراز هویت نمایش داده می‌شود، OAuth/Automatic را انتخاب کنید. Client ID، Client Secret یا کلید SSH دستی نیاز نیست؛ DCR از metadata کشف و اجرا می‌شود.
3. صفحهٔ ورود همین سامانه باز می‌شود. با حساب پنل و کد Authenticator وارد شوید و اجازهٔ اتصال را تأیید کنید. برای دسترسی مدیریتی از حساب `admin` استفاده کنید؛ صفحهٔ رضایت اختیار مدیریت حساب‌ها و مجوزها را جدا توضیح می‌دهد.
4. `Create as a plugin` / نصب اتصال را کامل کنید. در گفتگوی تازه، پلاگین مدار را با `@` انتخاب کنید.

این مسیر مطابق [راهنمای رسمی اتصال MCP و ایجاد پلاگین](https://developers.openai.com/plugins/deploy/connect-chatgpt) است. دسترسی به ساخت MCP سفارشی تابع مجوز حساب و workspace شماست. برای استفادهٔ شخصی/داخلی، ZIP سورس نرم‌افزار را به‌عنوان پلاگین آپلود نکنید؛ همان URL سرور را ثبت کنید. انتشار عمومی در فهرست پلاگین‌ها فرایند جداگانهٔ بررسی دارد.

## ورود پایدار

- access token ده دقیقه اعتبار دارد و کلاینت MCP آن را خودکار با refresh token تمدید می‌کند.
- مهلت عدم فعالیت refresh token به‌صورت پیش‌فرض ۹۰ روز است. هر تمدید موفق، توکن جدید و مهلت تازه می‌گیرد؛ استفادهٔ عادی نیازی به ورود روزانه یا ورود در هر گفتگو ندارد.
- باقی‌ماندن اتصال OAuth به بازبودن صفحهٔ مرورگر یا نشست هشت‌ساعتهٔ پنل وابسته نیست. این رفتار با کلاینت رسمی SDK و حذف نشست مرورگر در تست بررسی شده است.
- لغو اتصال، تغییر رمز/نقش/MFA، غیرفعال‌شدن حساب یا پایان مهلت عدم فعالیت، ورود دوباره را لازم می‌کند. ورود دائمی و غیرقابل‌لغو وعده داده نمی‌شود.
- اطلاعات اتصال GPT در دیتابیس پایدار می‌ماند. volume و `secrets/master_key` را هنگام راه‌اندازی مجدد حفظ کنید.

## دسترسی از پلاگین

مدیر با رضایت `gateway:manage` به ۱۸ ابزار دسترسی دارد. کاربران دیگر ۱۰ ابزار پایه را فقط در محدودهٔ مجوز خود دارند. حساب مدیر با scope قدیمی `servers:access` خودکار اختیار مدیریتی تازه نمی‌گیرد؛ برای دریافت scope جدید باید اتصال را یک بار دوباره مجاز کند.

| ابزار | کاربرد |
|---|---|
| `get_profile` | هویت و نقش حساب، وضعیت مجوز مدیریت |
| `list_servers` | سرورهای مجاز؛ مدیر، سرورهای غیرفعال و revision را نیز می‌بیند |
| `run_diagnostic` | پنج عیب‌یابی ثابت |
| `request_command` | درخواست اجرای دستور shell با تأیید انسانی |
| `get_job`، `list_jobs`، `cancel_job` | وضعیت، خروجی و لغو کارها |
| `list_connections`، `revoke_connection` | مشاهده و لغو اتصال‌های خود حساب |
| `get_management_link` | پیوند بخش امن پنل برای اطلاعات محرمانه یا تأیید دستور |
| `list_users`، `update_user_access` | مدیریت نقش و فعال‌بودن حساب‌ها؛ حفاظت از آخرین مدیر |
| `register_server` | ثبت سرور با تولید کلید Ed25519 در واسط و بازگرداندن فقط public key |
| `update_server` | تغییر نام/مقصد/وضعیت سرور با کنترل revision |
| `list_server_grants`، `set_server_grant` | مدیریت دسترسی کاربران به سرورها |
| `get_audit`، `get_gateway_settings` | گزارش رخدادها و محدودیت‌های اجرایی |

اطلاعات خصوصی مثل رمز حساب، MFA seed، کلید خصوصی و رمز SSH در چت یا خروجی ابزارها قرار نمی‌گیرد. ساخت حساب با رمز/MFA و تعویض اطلاعات محرمانهٔ موجود از صفحهٔ امن پنل انجام می‌شود؛ ابزار `get_management_link` مسیر آن را می‌دهد. افزودن سرور از MCP یک کلید خصوصی در واسط می‌سازد؛ برای برقراری اتصال، public key باید روی حساب مجاز مقصد نصب شود و fingerprint میزبان از منبع معتبر دریافت شده باشد.

تأیید اجرای دستور با ورود مجدد متفاوت است. دستورهای آزاد همچنان در پنل به تأیید انسانی نیاز دارند و ابزار تأیید خودکار در اختیار مدل نیست. پل SSH، فایل‌ها و اسکریپت‌ها را در حد مجوز حساب Linux اجرا می‌کند؛ داشتن حساب مدیر مدار، خودبه‌خود به کاربر Linux دسترسی root نمی‌دهد.

## راستی‌آزمایی پس از استقرار

1. با حساب مدیر وصل شوید و `get_profile` و `list_servers` را بخوانید.
2. یک عیب‌یابی بی‌خطر اجرا کنید و وضعیت/خروجی را با `get_job` بررسی کنید.
3. یک دستور بی‌خطر درخواست کنید؛ باید تا تأیید انسانی `pending` بماند.
4. بعد از انقضای access token و در یک گفتگوی تازه، بررسی کنید اتصال بدون ورود مجدد کار می‌کند.
5. با یک حساب محدود بررسی کنید ابزار مدیریتی و سرور غیرمجاز در دسترس نیستند.
6. اتصال را از پنل لغو کنید و بررسی کنید استفادهٔ بعدی نیاز به ورود دارد.

تست SDK محلی جای این آزمون با GPT واقعی و دامنهٔ مستقرشده را نمی‌گیرد. اگر قبلاً متصل بوده‌اید، پس از استقرار نسخهٔ تازه، در صفحهٔ اتصال `Refresh` را اجرا کنید تا ابزارها و metadata جدید کشف شوند.
